Project explanation (for technical and non-technical readers)

What it is  
A simple web app to upload files to Amazon S3. Each upload triggers an AWS Lambda function that uses Amazon Rekognition to detect inappropriate content. If flagged, the file is moved to a separate “flagged” bucket and removed from the main bucket.

Components  
- Frontend/Upload UI (index.php): Drag-and-drop (Dropzone) upload form.  
- Upload handler (file-upload.php): Receives files, uses AWS PHP SDK to put objects into the source S3 bucket.  
- AWS bootstrap (s3-object.php): Initializes AWS S3 client with your credentials, bucket name, and region.  
- Viewer (view_data.php): Lists objects currently in the source bucket with size and a link to open.  
- Lambda (lambda.py): Runs on S3 ObjectCreated events; calls Rekognition DetectModerationLabels. If labels are returned, copies the object to the flagged bucket and deletes it from the source. Logs to CloudWatch.

AWS resources used  
- S3 buckets: uploadfilesforverification (source), uploadfilesforverification-flagged (flagged).  
- IAM: user for PHP uploader with minimal S3 permissions; Lambda execution role with S3, Rekognition, and CloudWatch Logs permissions.  
- Lambda: image-moderation-function in eu-north-1 with an S3 trigger on ObjectCreated:*.

How it works end-to-end  
1) User opens the upload page and drops files.  
2) file-upload.php uploads each file to the source S3 bucket via AWS SDK.  
3) S3 event triggers Lambda. Lambda calls Rekognition to check for moderation labels.  
4) If flagged: Lambda copies the file to the flagged bucket and deletes it from the source. If clean: it stays in the source bucket.  
5) view_data.php lists the current contents of the source bucket and links to open files directly from S3.

Local setup summary  
- PHP 8.3 (portable) installed; php.ini configured with openssl and fileinfo.  
- Composer installed; AWS SDK added via composer require aws/aws-sdk-php.  
- PHP server run with: php -S localhost:8000 (from project root).

Security note  
- An AWS access key/secret were hard-coded in s3-object.php for setup. Rotate the key and move to environment variables before committing or publishing. Include /vendor/ in .gitignore; keep composer.lock tracked.***

Integrated AWS build guide (chronological narrative)

Project overview (AWS side)  
- Purpose: Automatically moderate uploaded images. Uploads go to S3; Lambda calls Rekognition to detect inappropriate content; flagged images move to a flagged bucket; safe images stay in the main bucket. Uses S3, Lambda, Rekognition, IAM, and CloudWatch.

Phase 1: IAM roles and permissions  
- Lambda execution role for logs: Created role in IAM (AWS service → Lambda) with policy AWSLambdaBasicExecutionRole to allow logs:CreateLogGroup, CreateLogStream, PutLogEvents. Role name: lambda-execution-role.  
- S3 access role for Lambda: Created role lambda-s3-file-verification-role (trusted entity Lambda). Added inline policy with s3:GetObject/s3:DeleteObject on arn:aws:s3:::uploadfilesforverification/* and s3:PutObject on arn:aws:s3:::uploadfilesforverification-flagged/*. Attached the inline policy.  
- Rekognition role: Created role lambda-rekognition-role (trusted entity Lambda) with inline policy allowing rekognition:DetectModerationLabels on "*".

Phase 2: Lambda function creation  
- Created Lambda function image-moderation-function in eu-north-1 (Python 3.14, x86_64).  
- Handler: lambda_function.lambda_handler; memory 512 MB; timeout 15s.  
- Attached execution role (lambda-execution-role) and then attached S3 and Rekognition policies.  
- Deployed moderation code (lambda.py) that reads S3 event, calls Rekognition, copies flagged images to uploadfilesforverification-flagged, deletes from source, logs to CloudWatch.

Phase 3: S3 trigger configuration  
- Added S3 trigger on bucket uploadfilesforverification for event type s3:ObjectCreated:* pointing to image-moderation-function. Verified trigger in Lambda overview.

Phase 4: Testing and debugging  
- First test revealed AccessDenied due to missing s3:ListBucket; policy updated to add s3:ListBucket on both buckets.  
- Safe image test: stays in source bucket; CloudWatch logs show “Image is safe.”  
- Flagged image test: copied to uploadfilesforverification-flagged and deleted from source; CloudWatch logs confirm copy/delete.

Current AWS resources  
- Buckets: uploadfilesforverification (source), uploadfilesforverification-flagged (flagged), region eu-north-1.  
- Roles/policies: lambda-execution-role (logs), lambda-s3-file-verification-role (S3 access inline policy), lambda-rekognition-role (Rekognition inline policy).  
- Lambda: image-moderation-function (Python 3.14, 512 MB, 15s) with S3 trigger on ObjectCreated:*.

Operational flow (end-to-end)  
1) User uploads via PHP UI → file-upload.php puts object into source bucket.  
2) S3 fires ObjectCreated event → Lambda runs.  
3) Lambda calls Rekognition DetectModerationLabels.  
4a) If labels found: copy to flagged bucket; delete from source; log actions.  
4b) If no labels: leave in source; log “Image is safe.”  
5) view_data.php lists objects currently in the source bucket with links to open.
